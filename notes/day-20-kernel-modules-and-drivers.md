# Day 20: Kernel Modules & Drivers (lsmod, modprobe)

## 1. Architectural Foundations: Loadable Kernel Modules (LKMs)

The Linux operating system is fundamentally a **Monolithic Kernel**. All core subsystems—memory management, scheduler, virtual filesystem, network stack, and hardware drivers—execute inside the same unsegmented **Ring 0 Supervisor Privilege Mode**, sharing a single address space.

However, unlike pure monolithic kernels that require full recompilation and rebooting to add a new driver, Linux supports **Loadable Kernel Modules (LKMs)**. Modules are compiled Executable and Linkable Format (**ELF**) relocatable object files (ending in `.ko`) that can be dynamically linked into the running kernel core at runtime.

## 2. Module Lifecycle: Loading, Linking & Dependency Resolution

```
                    User Executes: modprobe br_netfilter
                                    |
                                    v
                 Parses /lib/modules/$(uname -r)/modules.dep
               Identifies Dependencies: [bridge.ko, llc.ko]
                                    |
                                    v
       Calls finit_module() / init_module() System Calls in Order
       1. Loads llc.ko  -> 2. Loads bridge.ko -> 3. Loads br_netfilter.ko
                                    |
                                    v
                        Inside Kernel (Ring 0):
                 - Allocates Kernel Memory (vmalloc)
                 - Resolves Relocations via /proc/kallsyms
                 - Checks Kernel Version Magic & Taint Flags
                 - Executes Module Entry Point: init_module()
```

### 2.1 Low-Level Tools: `insmod` vs `modprobe`
- **`insmod` (Insert Module)**: Low-level tool. Requires full path to `.ko` file. **Does NOT resolve dependencies.** If `br_netfilter.ko` requires symbols from `bridge.ko`, `insmod` fails immediately with `Unresolved symbol` errors.
- **`modprobe`**: High-level, intelligent tool. Reads precompiled dependency maps (`modules.dep` generated by `depmod`), automatically loads all prerequisites in topological order, and applies parameter configurations from `/etc/modprobe.d/*.conf`.

## 3. Dissecting `/proc/modules` and `lsmod`

The `lsmod` command formats output from the kernel virtual file `/proc/modules`:

```bash
$ lsmod
Module                  Size  Used by
br_netfilter           32768  0
bridge                307200  1 br_netfilter
llc                    16384  2 bridge,stp
nvme                   49152  3
nvme_core             135168  4 nvme
```
- **`Module`**: Registered name of the kernel module.
- **`Size`**: Memory allocated in RAM for code and static data (in bytes).
- **`Used by`**: Number of active references (open file descriptors, network sockets) and names of dependent modules. **A module with `Used by > 0` cannot be unloaded.**

## 4. Writing a Compilable C Kernel Module (`hello_kernel.c`)

Writing kernel code requires strict adherence to kernel conventions:
- No standard C library (`libc` does not exist in Ring 0).
- `printf()` is replaced by `printk()` with log-level priority macros.
- Stack space is severely restricted (typically $8\text{ KB}$ or $16\text{ KB}$ total per kernel thread).

```c
#include <linux/init.h>
#include <linux/module.h>
#include <linux/kernel.h>

MODULE_LICENSE("GPL");
MODULE_AUTHOR("Prasun Nandi");
MODULE_DESCRIPTION("Enterprise Minimal LKM Example");
MODULE_VERSION("1.0");

static int __init enterprise_init(void) {
    printk(KERN_INFO "[+] Enterprise Module Loaded into Kernel Space!\n");
    return 0; // Return 0 indicates successful initialization
}

static void __exit enterprise_exit(void) {
    printk(KERN_INFO "[-] Enterprise Module Unloaded from Kernel Space!\n");
}

module_init(enterprise_init);
module_exit(enterprise_exit);
```

### The Accompanying `Makefile`:
```makefile
obj-m += hello_kernel.o

all:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) modules

clean:
	make -C /lib/modules/$(shell uname -r)/build M=$(PWD) clean
```

## 5. Kernel Taints & Stability Auditing

When troubleshooting unexplained kernel panics or instability, systems engineers inspect `/proc/sys/kernel/tainted`. If non-zero, the kernel was tainted by specific events:
- Bit 0 (`1`): Proprietary (out-of-tree / non-GPL) module loaded (e.g. NVIDIA proprietary driver).
- Bit 12 (`4096`): Out-of-tree module loaded without upstream kernel source approval.
- Bit 13 (`8192`): Unsigned module loaded on a SecureBoot-enforced system.
